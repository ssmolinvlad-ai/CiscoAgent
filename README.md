# CiscoAgent — Packet Tracer Lab Agent

Приложение Windows на Python/PySide6 для построения и проверки лабораторных в установленном Cisco Packet Tracer. Интерфейс на русском языке. Версия приложения: 0.1.0, экспериментальная.

## Запуск

1. Установите Python 3.11+ и самостоятельно откройте Cisco Packet Tracer. Практическая проверка выполнена на Windows 11 и Packet Tracer 9.0.0.0810.
2. Скачайте исходники этого репозитория и запустите `Prepare.cmd`. Он создаст локальную `.venv` и установит приложение вместе с `packet-tracer-mcp==0.11.0`.
3. В Cisco откройте Extensions → Scripting → Configure PT Script Modules → Add и выберите `integration/MCP-Control-Center.pts`. Включите модуль кнопкой Start.
4. Откройте `Запустить.cmd`. При первом подключении сервер моста создаёт локальный токен. Если модуль был открыт раньше, используйте Tools → Reload token → Run или перезапустите только модуль через Stop → Start.
5. **Оставьте окно MCP Control Center открытым** во время работы: проверенный канал требует работающего модуля. Загрузите `examples/Простая_сеть.txt` и нажмите «Начать выполнение».

Токен — локальный секрет моста, учётная запись Cisco для него не нужна. Если появляется `Security token missing`, сначала запустите приложение или `Восстановить подключение.cmd`, затем перечитайте токен в модуле. Скрипт использует токен, созданный настоящим сервером; он не генерирует подмену и не отключает проверки безопасности. При несовпадении каталогов сверяйте пути в сообщении модуля и документации upstream. Не публикуйте токен и не отправляйте его в issues.

В репозитории находятся исходники; готовая сборка EXE сюда не включена. Для сборки используйте `Build.cmd`. Если локально имеются готовые сборки, `Запустить.cmd` предпочитает комплект `bin/Verified`, затем `bin/Direct` и другие совместимые варианты.

Приложение работает только с уже открытым Cisco и никогда не запускает его самостоятельно. Это относится и к кнопке «Открыть готовый проект»: она использует мост работающего Cisco, предварительно сохраняя текущую сеть. При закрытом Cisco выполнение останавливается до анализа ИИ. Режим подготовки плана доступен без Cisco.

Вариант для разработчика: `python -m pip install ".[bridge,dev]"`, затем `python main.py`. `Build.cmd` собирает главное Windows-приложение в `bin/PacketTracerAgent` и отдельный процесс моста в `bin/PacketTracerBridge`. В собранном варианте отдельная установка Python не нужна; это комплект папок с EXE и библиотеками, а не единственный автономный файл.

В поставке используется PySide6-Essentials: это модули PySide6 QtCore, QtGui, QtWidgets без неиспользуемых WebEngine/Multimedia и других крупных дополнений.

## Что происходит после запуска

- Задание извлекается в фоновом потоке. PDF сохраняет текст и изображения всех страниц, включая векторные схемы; DOCX — абзацы, таблицы и изображения; PNG/JPG — изображение для vision-модели.
- Создаётся строгий план Pydantic. Проверяются IP, маски, шлюзы, имена, занятость портов, ссылки на устройства, покрытие требований проверками.
- Мост запускается как отдельный дочерний процесс по stdio. Приложение читает фактически доступные инструменты и их схемы.
- Проверяется подключение Cisco и каталог моделей/портов. Перед заменой текущей рабочей области сохраняется и проверяется `before-agent.pkt`. Новая рабочая область создаётся через документированный `AppWindow.fileNew(false)` внутри Script Engine, без диалога и без кликов.
- Создаются устройства и точные соединения. Настраиваются адреса, VLAN, IOS и службы Server-PT. Инфраструктура и серверы настраиваются раньше DHCP-клиентов.
- Проверяются фактическая модель, соединения, адреса/маски, шлюзы, DHCP, а также проверки из задания. Для маршрутизации, NAT, ACL и прочих требований план должен содержать соответствующие проверки состояния/трафика.
- Один ограниченный цикл исправлений повторяет базовую настройку IP/VLAN/DHCP указанных устройств. Произвольные пользовательские IOS-команды автоматически не переигрываются. Исправление любой возможной сетевой ошибки не обещается.
- Сохраняется настоящий `.pkt` через Packet Tracer, проверяется наличие непустого файла. Для имени на кириллице сохраняется нативный файл с ASCII-именем и копируется под точным именем задания. JSON-план не подменяет `.pkt`.
- Отчёты HTML/JSON показывают успешные, неуспешные и неподтверждённые проверки. История первой ошибки сохраняется даже после исправления.

Результаты по умолчанию: `Документы/PacketTracerLabs/<дата_время_идентификатор>/`. В каждой папке — план, журнал, фактические ответы Cisco, отчёт, резервная копия и итоговый проект, если сохранение удалось. Папка `native` содержит исходный файл, сохранённый Cisco.

## Простой режим без API

Откройте `examples/Простая_сеть.txt`. Поддерживается русская и английская структурированная запись:

```text
название: Моя сеть
файл: lab.pkt
устройство SW1 switch 2960-24TT
устройство PC1 pc PC-PT
устройство PC2 pc PC-PT
связь PC1:FastEthernet0 SW1:FastEthernet0/1 straight
связь PC2:FastEthernet0 SW1:FastEthernet0/2 straight
адрес PC1 FastEthernet0 192.168.10.10/24
адрес PC2 FastEthernet0 192.168.10.20/24
пинг PC1 192.168.10.20 allow
```

Английские варианты: `title`, `file`, `device`, `link`, `ip`, `ping`. Дополнительно: `dhcp PC1`, `vlan SW1 10 STAFF`, блок `ios R1:` … `end-ios`. В блоке IOS задаются команды из режима конфигурации; исполнитель сам добавляет `enable`, `configure terminal`, `end` и сохраняет startup-config.

JSON-план по схеме `LabPlan` можно загрузить как `.json` или JSON в `.txt`. Неизвестная строка не пропускается: приложение требует ИИ или структурированный план. Это предотвращает незаметную потерю требований. Без API нет универсального понимания свободного текста или OCR.

## Подключаемый ИИ

Включите флажок использования ИИ. Провайдер должен поддерживать Chat Completions, JSON mode и изображения для схем. Переменные окружения:

| Переменная | Смысл |
|---|---|
| `LAB_AI_ENDPOINT` | Полный HTTPS URL endpoint Chat Completions; локальный HTTP допускается только localhost/127.0.0.1 |
| `LAB_AI_MODEL` | Точный идентификатор доступной пользователю модели |
| `LAB_AI_KEY` | API-ключ; читается только из окружения |
| `PACKET_TRACER_EXE` | Необязательный явный путь к PacketTracer.exe |
| `PT_BRIDGE_PYTHON` | Python среды с packet-tracer-mcp, если она отличается от среды приложения |
| `PT_AGENT_RESULTS` | Другая папка результатов |

Ключи не встроены в код и не запрашиваются в чате. ChatGPT-подписка не предоставляет приложению API-доступ. При включённом ИИ текст и изображения задания отправляются выбранному провайдеру. Для простого структурированного задания API не используется даже при установленном флажке. Интерфейс `Planner` позволяет добавить другой протокол или локальную модель.

Неоднозначность сначала разрешается по таблицам, тексту и рисункам. Предположения записываются в план. Если существенные данные остаются неизвестными, поле `unresolved` останавливает выполнение с конкретным вопросом в отчёте. Программа не выбирает произвольные порты вместо требуемых.

## Управление и ограничения

Пауза/остановка применяются между операциями. Уже отправленная команда Cisco или API-запрос завершается перед остановкой (тайм-аут операции моста 180 секунд). Программа не завершает Cisco принудительно и не откатывает изменённую сеть автоматически. При ошибке после начала сборки частичный проект остаётся в Cisco; исходная лабораторная сохраняется отдельно перед сборкой.

Основной исполнитель работает через MCP/Script Engine. `WindowsDesktop` использует pywinauto для окон и диалогов; предусмотрено распознавание шаблона OpenCV + Pillow/PyAutoGUI с проверкой уверенности. Универсального распознавания всех пиктограмм Cisco нет, шаблоны интерфейса не подменяются выдуманными координатами. Нераспознанные окна/диалоги останавливают операцию. Вход в Cisco и пароли пользователь вводит самостоятельно.

Реализация рассчитана на обычные топологии Ethernet IPv4 и модели с портами в каталоге моста. Дополнительные аппаратные модули, произвольные .pka с ограничениями, сложные IoT/OT, IPv6, все особенности ASA/беспроводных клиентов пока не реализованы. Настройка IOS ограничивается тем, что поддерживает выбранная модель Packet Tracer. Приложение не управляет настоящими сетевыми устройствами.

## Проверка разработки

`python -m pytest -q` запускает проверки валидации, чтения файлов, API через подставной сервер, управления паузой/остановкой, отчётов и исполнителя через имитатор. Тестовый маркер `.pkt` в имитаторе специально не является файлом Cisco. Успех этих тестов не доказывает живую совместимость с Packet Tracer.

Практическая проверка 6 ноября 2026: агент построил SW1 + PC1 + PC2, сохранил настоящий `.pkt`, повторно открыл его и подтвердил ping в обе стороны (4/4). Всего 9 проверок отчёта прошли. Подробности и границы проверки: [docs/VALIDATION.md](docs/VALIDATION.md).

![Топология, построенная агентом в Packet Tracer](docs/topology.png)

Этот результат подтверждает простой сценарий Ethernet IPv4. Сложные лабораторные и все сетевые службы не прошли такую же сквозную проверку.

Оригинальное расширение MCP Control Center включено с MIT-лицензией upstream. Лицензионные тексты зависимостей сохранены в `third-party/`. PyMuPDF распространяется на условиях AGPL либо коммерческой лицензии; наличие публичного репозитория не отменяет условия зависимостей. Отдельная лицензия на собственный код проекта пока не выбрана. Cisco Packet Tracer устанавливается отдельно и не входит в поставку.
