# Лабораторная №5: состояние сценария 0.2.1

Методичка прочитана полностью. В ней восемь этапов: построение схемы варианта и по одному ПК на роутер; адреса LAN/WAN с маской /24; show ip interface brief; отрицательный ping до маршрутов; статические маршруты; show ip route; положительный ping после маршрутов; tracert минимум в три сети.

На второй странице находятся ссылки на схемы вариантов 1–18. Самих рисунков в PDF нет. При открытии ссылки варианта 4 сайт сообщает «Владелец не открыл доступ по ссылке». Поэтому точная топология этого варианта пока неизвестна. Пример из теоретического раздела не заменяет вариант.

Добавлен `course_static.py`. Исполнитель принимает явно переданный LabPlan JSON точной схемы и проверяет его до построения: минимум три роутера, по одному ПК, уникальные /24, правильные шлюзы, связный граф, отсутствие заранее заданных маршрутов и посторонних служб. Затем он выполняет восемь этапов и сохраняет наблюдения. Статические маршруты включают обратные направления и удалённые WAN, чтобы трассировки могли возвращать ответы. Без плана программа останавливается, не выбирая тестовую сеть.

Проверки разработки: 88 passed, 1 skipped. Добавлены проверки следующего перехода, обратного пути и удалённых WAN, отклонения несвязного графа, неверного шлюза, маски и предварительных маршрутов. Общая функция tracert для №5–7 теперь выбирает три разных назначения.

Живой прогон №5 и повторные персональные прогоны №6/7 не выполнены. Канал MCP сообщил отсутствие подключения; захват открытого окна Cisco дважды завершился тайм-аутом. Cisco не перезапускался. Ранее пройденные проверки №6/7 относятся только к тестовому стенду версии 0.2.0 и не объявляются повторными проверками нового кода.

Для завершения нужны два условия: доступная схема варианта 4 (рисунок, экспорт или открытая исходная страница) и работающее окно MCP Control Center в уже открытом Cisco. После этого сначала строится и проверяется №5; №6 и №7 запускаются отдельно на копиях результата №5.
