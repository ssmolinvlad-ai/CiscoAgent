# Проверка версии 0.1.0

Дата практической проверки: 6 ноября 2026. Windows 11, Cisco Packet Tracer 9.0.0.0810, packet-tracer-mcp 0.11.0, MCP Control Center 0.6.1 (интерфейс v6).

## Реальная лабораторная

Исполнитель приложения создал коммутатор SW1 (2960-24TT), компьютеры PC1 и PC2 (PC-PT). Соединения: PC1 FastEthernet0 → SW1 FastEthernet0/1, PC2 FastEthernet0 → SW1 FastEthernet0/2, медные straight-through. Адреса: 192.168.10.10/24 и 192.168.10.20/24.

Прочитаны фактические модели, соединения и адреса. Девять проверок отчёта завершились успешно. Проверен ping в обе стороны: по четыре ответа из четырёх. Сохранён настоящий файл Cisco `.pkt` (48 406 байт), затем повторно открыт в работающем Cisco. После повторного открытия понадобилось ускорить симуляцию для сходимости STP; затем ping снова прошёл в обе стороны (4/4). Снимок `topology.png` получен из настоящего Cisco.

Перед изменением рабочей области сохранена резервная копия. Она и личные диагностические журналы не публикуются. Исполнитель проверялся напрямую; эти результаты не означают, что каждая кнопка последней собранной GUI-версии проверена вручную.

## Автоматические тесты

50 тестов прошли, 1 тест живого контракта пропущен по умолчанию. Отдельная проверка установленного моста выполнялась дополнительно. Обычные тесты используют имитацию ответов, а не установленный Cisco; их успех сам по себе не подтверждает выполнение лабораторной.

## Ограничения

- Подтверждена простая сеть Ethernet IPv4; сложные NAT/ACL/маршрутизация/службы требуют отдельных живых проверок.
- Окно MCP Control Center должно оставаться открытым. Файловый канал при закрытом окне не подтверждён.
- Приложение подключается только к уже запущенному Cisco, включая открытие готового проекта.
- Произвольные ограниченные PKA, дополнительные аппаратные модули, IPv6 и сложные IoT/OT пока не поддерживаются.
- Первичная установка Python-зависимостей требует интернета; ИИ для свободных заданий требует отдельного API-доступа.
